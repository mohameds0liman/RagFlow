# M2 — Auth & Theme Toggle

## What was built

### Auth system
- **`authApi.js`** — 5 endpoints: `loginApi`, `registerApi`, `logoutApi`, `forgotPasswordApi`, `resetPasswordApi`. JWT attached via axios interceptor automatically.
- **`authSlice.js`** — 3 async thunks (`login`, `register`, `logout`). Stores `access_token`, `refresh_token`, `role`, `user` in Redux + localStorage. Clears on logout/401.
- **`Login.jsx`** — Formik + Yup validation, password visibility toggle (eye icon), error display via notistack, role-based redirect (admin → `/admin/dashboard`, user → `/chat`).
- **`Register.jsx`** — Username/email/password/confirm with Yup validation (min 8 chars, letters + numbers), **password strength indicator** with 3-requirement checklist + LinearProgress bar (Weak/Medium/Strong).
- **`ForgotPassword.jsx`** — Email submission + success state screen.

### Light/Dark theme toggle
- **`themeSlice.js`** — Redux slice with `mode` state, `toggleTheme`/`setTheme` actions, persisted to `localStorage('theme_mode')`. Default: `'light'`.
- **`theme/index.js` rewrite** — `getTheme(mode)` factory returning a full MUI `createTheme()` with:
  - **Light palette**: `#ffffff` bg, `#fafafa` paper, `#2196f3` primary, `#673ab7` secondary, `#212121` text, `#eeeeee` divider — exact Flowise light mode
  - **Dark palette**: `#191b1f` bg, `#23262c` paper, `#7c4dff` primary, `#bdc8f0` text, `#32353b` divider — exact Flowise dark mode
  - Component overrides for Drawer, AppBar, Button, TextField, Select, MenuItem, IconButton, Chip, Dialog, Table, Tooltip, Menu
- **`App.jsx`** — wraps routes in `<ThemeProvider theme={getTheme(mode)}>` so theme is reactive
- Toggle button (sun/moon icon) in both **AdminLayout** and **UserLayout** topbars

### Theme-aware conversion (all files)
Every component and view was converted from hardcoded hex colors → `theme.palette.*` via `useTheme()`:
- `MainCard` — bg, border, title, divider
- `ConfirmDialog` — title, content, cancel button
- `StatusChip` — semantic status colors use `palette.success/error/warning/primary.main` with alpha bg; neutral states use `palette.action.hover` / `palette.text.secondary`
- `StyledDataGrid` — all backgrounds, borders, text, icons, pagination
- `Login`, `Register`, `ForgotPassword` — page bg, card, avatar, headings, links
- `AdminLayout` — AppBar bg, main content area, sidebar border, avatar, breadcrumb text
- `UserLayout` — AppBar bg, main content, avatar, brand text
- `UserChat` (placeholder) — text colors

## Problems & solutions

1. **CORS login response shape**: Backend returns `{ access_token, user: { role, ... } }`. Frontend reads `data.user.role`, not flat `data.role`. Solved by checking both `result.payload.user?.role || result.payload.role`.
2. **Refresh token is HTTP-only cookie**: Not in JSON body. Axios must use `withCredentials: true` to send cookie on `/auth/refresh`. Already configured in `axiosInstance.js`.
3. **Backend register validation**: Rejects passwords under 8 chars or without letters+numbers. Yup rules match exactly.
4. **Password eye toggle unreliability**: `<Field as={TextField}>` with MUI InputAdornment was fragile. Rewrote as `useField` hook + `<FormControl>` + `<OutlinedInput>` directly for reliable adornment rendering.
5. **Hardcoded dark colors everywhere**: Login, Register, ForgotPassword, MainCard, ConfirmDialog, StyledDataGrid, StatusChip, UserChat, AdminLayout, UserLayout all used `#1A1F2E`, `#1E2330`, `#2D3448`, `#E0E0E0`, `#9099B0` etc. Systematically replaced every occurrence with `theme.palette.*` using `useTheme()`.
6. **Theme not reactive**: Theme was created once outside component. Moved into `App.jsx` using `useMemo` so it re-creates whenever `theme.mode` changes.

## What NOT to touch

- `axiosInstance.js` — JWT interceptor and cookie-based refresh are correct
- `authSlice.js` — login/register thunk logic matches backend shape; do not flatten response
- `theme/index.js` palette tokens — these are the single source of truth; do not add inline overrides
- Backend auth response shape (`data.user.role`) — cannot be flattened without backend changes
- Do NOT add `window.confirm()` — always use `ConfirmDialog` component
- Do NOT add raw `axios` imports — always use `api` from `axiosInstance.js`
