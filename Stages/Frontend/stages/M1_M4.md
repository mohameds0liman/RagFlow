## M1 — Scaffold & Design System

### What was built
- **Vite + React project** in `Frontend/` with deps: MUI, Emotion, Tabler Icons, Redux Toolkit, React Router, Axios, Formik+Yup, notistack, fetch-event-source, react-markdown
- **Flowise-identical dark theme** (`src/theme/index.js`): bg `#1A1F2E`, sidebar `#171C2B`, card `#1E2330`, surface `#232839`, primary `#4B72FF`, text primary `#E0E0E0`, text secondary `#9099B0`, border `#2D3448`, Inter font, `12px` border radius, `260px` sidebar, `64px` topbar
- **4 shared components**: `MainCard` (card wrapper), `ConfirmDialog` (destructive confirm modal), `StatusChip` (semantic status badge), `StyledDataGrid` (pre-styled MUI X DataGrid)
- **Redux store** with 4 slices: `authSlice`, `kbSlice`, `chatbotSlice`, `usersSlice`
- **Layouts**: `AdminLayout` — 260px sidebar with 5 nav items (Dashboard, Document Stores, Chatbots, Chat, Users), active indicator (`border-left: 4px solid #4B72FF`), 64px topbar with user menu + logout. `UserLayout` — minimal topnav bar
- **Route guards**: `AdminRoutes` (checks `role === 'admin'`), `UserRoutes` (checks `role === 'user'`)
- **Placeholder admin views** — stub components for all 5 nav pages

### Problems solved
- **Sidebar active detection**: Chatbots path (`/admin/chatbots`) matched Chat (`/admin/chat`). Fixed by requiring `startsWith` on path + `/` suffix.
- **Hardcoded colors in Layout**: Replaced with `theme.palette` in M2.

## M2 — Auth & Theme Toggle

### What was built
- **`authApi.js`** — 5 endpoints: login, register, logout, forgot-password, reset-password. JWT via axios interceptor.
- **`authSlice.js`** — 3 async thunks (login, register, logout). Stores `access_token`, `refresh_token`, `role`, `user` in Redux + localStorage. Clears on logout/401.
- **`Login.jsx`** — Formik+Yup validation, password visibility toggle, error via notistack, role-based redirect (admin → `/admin/dashboard`, user → `/chat`).
- **`Register.jsx`** — Username/email/password/confirm with Yup (min 8 chars, letters+numbers), password strength indicator with checklist + LinearProgress bar.
- **`ForgotPassword.jsx`** — Email submission + success state screen.
- **`themeSlice.js`** — Redux slice with `mode` state, `toggleTheme`/`setTheme`, persisted to `localStorage('theme_mode')`. Default: `'light'`.
- **`theme/index.js` rewrite** — `getTheme(mode)` factory returning full MUI `createTheme()` with light + dark palettes (exact Flowise colors). Component overrides for Drawer, AppBar, Button, TextField, Select, MenuItem, IconButton, Chip, Dialog, Table, Tooltip, Menu.
- **`App.jsx`** — wraps routes in `<ThemeProvider theme={getTheme(mode)}>` so theme is reactive.
- **Toggle button** (sun/moon icon) in both AdminLayout and UserLayout topbars.
- **All components converted** from hardcoded hex → `theme.palette.*`: MainCard, ConfirmDialog, StatusChip, StyledDataGrid, Login, Register, ForgotPassword, AdminLayout, UserLayout, UserChat.

### Problems solved
1. **CORS login response shape**: Backend returns `{ access_token, user: { role, ... } }`. Frontend reads `data.user.role || data.role`.
2. **Refresh token is HTTP-only cookie**: Axios uses `withCredentials: true` on `/auth/refresh`. Already in `axiosInstance.js`.
3. **Password eye toggle unreliability**: Rewrote as `useField` hook + `<FormControl>` + `<OutlinedInput>` directly.
4. **Hardcoded dark colors everywhere**: Systematically replaced with `theme.palette.*` via `useTheme()`.
5. **Theme not reactive**: Moved `createTheme` into `App.jsx` with `useMemo` so it re-creates on `theme.mode` change.

## M3 — Document Stores (Full CRUD + Ingest/Upsert Pipeline)

### What was built
- **DocumentStoreList** — KB card grid (`repeat(3, 1fr)`, `aspectRatio: 5/2`), KB stats (documents/chunks/chatbots count), StatusChip + "Configured" chip, context menu (Edit/Delete via IconDots), Create/Edit dialog (Name+Description), Delete via ConfirmDialog.
- **DocumentStoreDetail** — Breadcrumbs, toolbar (Upload + Upsert Config buttons), document card grid (same layout), per-doc metadata (StatusChip, file_type, file_size_mb, chunks_count chips), per-doc actions: Load (opens IngestStatusDialog), Upsert (spinning ring + green check on success), View&Edit Chunks (opens ChunksViewDialog), Delete (red, ConfirmDialog). Empty state with Upload CTA.
- **UpsertionConfigDialog** — 3 config section cards (Embedder, Vector Store, Record Manager), component selector from `/admin/components?category=X`, dynamic field schema from `/admin/components/:name/schema`, field rendering (enum→Select, integer/number→numeric, text→text), save/update, prefill from existing config, auto-select first component.
- **IngestStatusDialog** — Loader + Chunker cards, select from `/admin/components?category=loader`/`chunker`, Chunk Size + Overlap numeric inputs, Ingest button dispatches `ingestDocument`.
- **ChunksViewDialog** — StyledDataGrid (chunk_no, page_content 3-line clamp, status colored, actions), Edit (multiline TextField), Delete (ConfirmDialog).
- **UploadDocumentDialog** — Drag-and-drop zone with hover, file validation (.pdf .docx .txt .csv .html .md .json), simulated progress bar (15% increments to 85%, jump to 100%), FormData upload thunk.
- **StatusChip** — Full status map (lowercase + title-case): pending, uploaded, processing, ready, error, active, inactive, embedded, completed, Granted/Revoked, Configured. Semantic colors mapped.
- **kbSlice** — Async thunks: fetchKnowledgeBases, create/update/delete KB, fetchDocuments, upload/delete document, ingestDocument, fetch/update/delete chunks, triggerUpsert, fetchStatus. Loading states: loading, documentLoading, chunkLoading, ingestLoading, upsertLoading.
- **knowledgeBaseApi** — All endpoints implemented. `triggerUpsert` sends `JSON.stringify(docId)` (raw string, not object wrapper).
- **Login title** changed from "Welcome to RAGFlow" → "RAGFlow".

### CRITICAL problems solved
1. **`listComponents(category)` returns object, not array**: API returns `{ "PyPDFLoader": {...} }`. Must convert with `Object.entries(data || {}).map(([name, inputs]) => ({ name, inputs }))` everywhere.
2. **Backend category names**: Hardcode 3 config section keys: `embedder`, `vector_store`, `record_manager`.
3. **MUI Grid unreliable for 3-column**: Use raw CSS grid: `display: 'grid', gridTemplateColumns: 'repeat(3, 1fr)', gap: 3` on `<Box>`.
4. **Card aspect ratio**: Iterated `1/1` → `5/2`. Final: `aspectRatio: '5/2'`, name `1.3rem` (KB) / `1rem` (docs), stats `0.9rem`, icons 20-24px, action buttons 32×32 with 18px icons.
5. **`POST /upsert` returns 422**: Backend uses `doc_id: str = Body(...)` without `embed=True`. FastAPI expects raw JSON string literal, not object. **Fix**: Send `JSON.stringify(docId)` instead of `{ doc_id: docId }`. Located in `knowledgeBaseApi.js:57`. Do NOT revert unless backend adds `embed=True`.
6. **FastAPI 422 detail is array, not string**: Use `typeof err === 'string' ? err : JSON.stringify(err?.response?.data || err)` for snackbar.
7. **Backend missing `chunks_count` per doc**: Backend modified (admin.py:449) to add `extras=loader_counts(d.id, db)`. Frontend reads `doc.chunks_count ?? 0`.
8. **Upsert button feedback**: 3-state icon: idle (IconCloudUpload blue), loading (CircularProgress ring overlay), success (green IconCircleCheckFilled 2s). No success snackbar. `recentUpsert` stores document ID for per-doc tracking.
9. **Form field convention**: Fields use `placeholder={String(field.default)}` with no `helperText` or `required` prop. Intentional.

## M4 — Chatbots (Full CRUD + Settings Dialog)

### What was built
- **`chatbotApi.js`** — 5 functions: listChatbots, getChatbot, createChatbot, updateChatbot, deleteChatbot. Returns `{ status, chatbot }` or `{ status, count, chatbots }`.
- **`chatbotSlice.js`** — 5 async thunks: fetchChatbots, fetchChatbotById, createChatbot, updateChatbot, deleteChatbot. State: `{ list, selectedChatbot, loading, saving, error }`. `updateChatbot.fulfilled` updates both `list[idx]` and `selectedChatbot`.
- **ChatbotList** — Card grid `repeat(3, 1fr)` matching M3, bot name `1.3rem`, StatusChip, KB name with IconDatabase, sessions count, LLM badge (IconRobot + Chip with `bot.llm_config.name`). Three-dot menu: Edit (opens ChatbotSettingsDialog), Open Chat (navigates to `/admin/chat`), Delete (ConfirmDialog). Add Chatbot button. Empty state. No click-to-navigate on cards.
- **ChatbotSettingsDialog** — Single dialog for create+edit driven by `existingBot` prop. Full `maxWidth="md"`. 6 card sections: Basic Info (Name+Description), Knowledge Base (select from kbSlice), LLM Configuration (provider from `/admin/components?category=chat_model` + dynamic schema fields), Chain & Memory (chain_type select, memory_type select), Instructions/Prompt Template (multiline 6 rows). Save builds payload matching backend `CreateChatbotRequest` exactly.
- **App.jsx** — `/admin/chatbots/:id` redirects to `/admin/chatbots` via `<Navigate replace />`. ChatbotEditor import removed.

### Problems solved
1. **Redundant create dialog + editor page**: Consolidated into single ChatbotSettingsDialog with create/edit mode via `existingBot` prop.
2. **`listComponents('chat_model')` returns object**: Same `Object.entries()` conversion as M3.
3. **Payload shape must match backend**: Exact shape: `{ name, description, store_id, llm_config: { name, build_config }, chain_config: { chain_type }, memory_config: { memory_type }, prompt_config: { template } }`. `store_id` sent as `null` when no KB. `llm_config.name` = provider name.
4. **LLM defaults need `?? ''` not `|| ''`**: `||` overwrites falsy valid values like `0` for temperature. Use `?? ''`.
5. **Leftover ChatbotEditor import**: Removed from App.jsx, file kept as `<Navigate to="/admin/chatbots" replace />` redirect.

2. **Backend trailing space in ChatOllama input name**: `InputParam(name="temperature " , ...)` — backend bug, cannot fix from frontend.
3. **Live chat preview moved from dialog to sidebar**: Removed from ChatbotSettingsDialog, added collapsible right settings panel in AdminChat.
4. **Session auto-creation**: Auto-creates session when selected chatbot has none (both AdminChat and UserChat).

## CROSS-CUTTING RULES (Do NOT touch)

### API Layer
- Every API call MUST import `api` from `src/api/axiosInstance.js` — never import raw `axios`.
- JWT token attached automatically. On 401, interceptor auto-refreshes via `POST /auth/refresh`. Never handle 401 manually.
- File uploads MUST use `FormData` with `Content-Type: multipart/form-data`.
- Always extract error messages from `err.response?.data?.detail` (FastAPI format).

### `listComponents(category)` returns OBJECT not array
- Every call to `/admin/components?category=X` returns `{ Name: [inputs] }`.
- Always convert: `Object.entries(data || {}).map(([name, inputs]) => ({ name, inputs }))`.

### Backend endpoints using `Body()` without Pydantic model
- These expect raw JSON values, not JSON objects.
- Check `"loc"` in 422 errors: if `"loc":["body"]` (no field name), body format is wrong.
- `triggerUpsert` sends `JSON.stringify(docId)` — do NOT wrap back to `{ doc_id: docId }` unless backend adds `embed=True`.
- `knowledgeBaseApi.js:57` — this is the fix location.

### CSS grid layout
- Both KB list and doc detail views use `display: 'grid', gridTemplateColumns: 'repeat(3, 1fr)', gap: 3`.
- Card `aspectRatio: '5/2'` — tuned iteratively. Changing it requires rescaling all fonts/sizes/chips.
- Do NOT revert to MUI `<Grid>`.

### StatusChip
- Every status variant (lowercase AND title-case) must be in the color map. New statuses without map entries show neutral gray.
- Add both cases when adding new statuses.

### Theme
- `theme/index.js` palette tokens are single source of truth. No inline overrides.
- Theme is reactive via `useMemo` in `App.jsx`.

### Form field convention
- Config dialog fields use `placeholder={String(field.default)}` with no `helperText` or `required` prop. Intentional.
- LLM defaults use `?? ''` (nullish coalescing), not `|| ''`.

### Payload shapes
- **Chatbot create/update**: `{ name, description, store_id, llm_config: { name, build_config }, chain_config: { chain_type }, memory_config: { memory_type }, prompt_config: { template } }`
- `llm_config.name` = provider name. `build_config` values must be typed correctly (numbers for temperature, strings for URLs).
- `store_id` sent as `null` when no KB selected.

### ChatWindow
- Keep as pure presentational component. Display and input only, never API calls.

### Chunks
- Upsert button lives on document card in DocumentStoreDetail, NOT inside ChunksViewDialog.
- Do NOT add upsert back to ChunksViewDialog.

### Auth
- Backend auth response: `{ access_token, user: { role, ... } }`. Frontend reads `data.user.role || data.role`.
- Refresh token is HTTP-only cookie. Handle via `withCredentials: true` in `axiosInstance.js`.
- On logout/401: clear localStorage, clear Redux, redirect to `/login`.

## BACKEND DEPENDENCIES (frontend cannot fix)

1. **`chunks_count` per document**: Backend `admin.py:449` adds `extras=loader_counts(d.id, db)`. Without it, `doc.chunks_count` is `undefined` (shows `0` via `?? 0`).
2. **`POST /upsert` body format**: Backend uses `doc_id: str = Body(...)` without `embed=True`. If backend adds `embed=True`, frontend can switch back to `{ doc_id: docId }`.
3. **Category names**: Backend `registry.list_all_categories()` determines categories. Frontend hardcodes `['embedder', 'vector_store', 'record_manager', 'loader', 'chunker', 'chat_model']`. If backend renames a category, update accordingly.
4. **Chatbot endpoint response shape**: `POST /admin/chatbots` returns `{ status: "created", chatbot: {...} }`, `GET /admin/chatbots` returns `{ status, count, chatbots: [...] }`.
5. **ChatOllama trailing space bug**: `InputParam(name="temperature " , ...)` in backend. `build()` looks up `config["temperature"]` (without space). KeyError. Cannot fix from frontend.
6. **`chain_config` behavior**: Backend stores chain config but `updateChatbot` only supports updating `chain_type` currently.
