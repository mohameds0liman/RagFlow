## Problems & solutions

### 1. `temperature` pipeline error — missing / type-mismatched field
**Problem**: `POST /admin/chatbots/{chatbot_id}/sessions/{session_id}/chat` returned "Chat pipeline error: 'temperature'". Two distinct causes:

1. **Type mismatch** — TextField values are always strings (`"0.7"`), but `ChatOllama.build()` expects `temperature` to be a float. The backend `ChatOllama` received `"0.7"` instead of `0.7` and LangChain raised an error.
2. **Missing key** — The `typedConfig` builder only included fields the user interacted with (`if (field.name in form.llm_config)`). If the user left `temperature` empty (expecting the placeholder default `0` to apply), the key was **omitted entirely** from `build_config` → `ChatOllama.build()` called `config["temperature"]` → **KeyError**.

**Solution (type mismatch)**: Added `castValue(value, type)` that converts string inputs to numbers based on the schema `type` field. Applied in both `ChatbotSettingsDialog.jsx` and `AdminChat.jsx`.

**Solution (missing key)**: The `typedConfig` builder now includes **all** schema fields. When the user hasn't provided a value, it falls back to the schema's `default`. If neither exists, the field is skipped. See "typedConfig default fallback" fix below.

### 2. ChatOllama input name — misreported trailing space (false alarm)
**Verified**: `InputParam(name="temperature", type="float", default=0)` in `ChatOllama.py` is **correct** — no trailing space. The earlier claim was a misread. The actual space is after the closing quote and before the comma (`name="temperature" ,`), which is just Python formatting and does not affect the serialized name.

### 3. Live chat preview moved from dialog to sidebar panel
**Problem**: Original M5 spec put live chat preview inside ChatbotSettingsDialog. User requested removing it from there and instead adding a full settings panel to the AdminChat page where the admin can tune settings while chatting live.
**Solution**: 
- Removed live chat preview from `ChatbotSettingsDialog.jsx`
- Removed "Edit Instructions" button from AdminChat top bar
- Added collapsible right settings panel to `AdminChat.jsx` with all chatbot config (name, description, KB, LLM, chain, memory, prompt template) + "Update Settings" save button
- The settings panel is toggled via a gear icon button in the top bar

### 4. Session auto-creation on chatbot select
**Problem**: When selecting a chatbot, if no sessions exist, the message "Select a chatbot" was shown but user couldn't start chatting immediately.
**Solution**: Both AdminChat and UserChat auto-create a session when the selected chatbot has none.

## Fixes applied during M5 review

1. **AdminChat.jsx: selectedChatbot not updated after settings save** — `handleUpdateSettings` now captures the thunk result and updates local `selectedChatbot` state via `setSelectedChatbot(result)`.

2. **AdminChat.jsx: store_id missing from update payload** — Added `store_id: settingsForm.store_id || null` to the payload sent to `updateChatbot` thunk. Note: backend `UpdateChatbotRequest` doesn't support `store_id` yet (backend limitation).

3. **AdminChat.jsx: missing fetchKnowledgeBases()** — Added `dispatch(fetchKnowledgeBases())` to the useEffect so the KB dropdown in the settings panel is populated when navigating directly to `/admin/chat`.

4. **.env: empty VITE_API_URL** — Fixed from empty to `http://127.0.0.1:8000`.

5. **Both files: typedConfig omits untouched schema fields** — In `ChatbotSettingsDialog.jsx` and `AdminChat.jsx`, the `typedConfig` builder used `if (field.name in form.llm_config)` which excluded any schema field the user never interacted with. Fields with schema defaults (like `temperature: 0`) were silently dropped if the user left the input empty. Replaced with fallback logic:
   ```js
   const raw = form.llm_config[field.name];
   const value = (raw !== undefined && raw !== '') ? raw : field.default;
   if (value !== undefined && value !== null) {
     typedConfig[field.name] = castValue(value, field.type);
   }
   ```
   This ensures all schema fields are always sent, using defaults when user input is absent.

## What NOT to touch

- **`castValue()` in both files** — This handles the numeric type conversion for LLM config fields. If new component types are added (e.g., `"boolean"`), extend this function.
- **`NUMERIC_TYPES` constant** — Used in both files for `type` attribute on TextField and for cast logic. Keep in sync.
- **`typedConfig` default fallback pattern** — Both `ChatbotSettingsDialog.jsx` and `AdminChat.jsx` now use the same pattern: `const value = (raw !== undefined && raw !== '') ? raw : field.default`. This ensures ALL schema fields are included in `build_config`, even if the user never touched them. If you modify how `typedConfig` is built, keep this fallback logic intact — otherwise the same `temperature`-style crash will reappear for any optional schema field with a default.
- **`ChatWindow.jsx`** — Keep it as a pure presentational component. It should only handle display and input, never API calls.
- **Settings panel collapse state** — Uses `showSettings` useState. Resets to false when selecting a different chatbot.
- **`llm_config.build_config` shape** — Must be `{ name: "ChatOllama", build_config: { base_url, model, temperature } }`. Values in `build_config` must be typed correctly (numbers for temperature, strings for URLs).
- **`Object.entries()` conversion for component schemas** — Same as M3/M4. `listComponents` returns an object, not an array.
