# M5 — Chat System

## What was built

### chatApi (`api/chatApi.js`)
- **12 API functions** covering both Admin and User chat endpoints:
  - Admin: `adminCreateSession`, `adminListSessions`, `adminDeleteSession`, `adminListMessages`, `adminSendMessage`
  - User: `userListChatbots`, `userCreateSession`, `userListSessions`, `userDeleteSession`, `userListMessages`, `userSendMessage`
- Uses `api` from `axiosInstance.js` — JWT handled automatically

### ChatWindow (`components/ChatWindow.jsx`)
- **Message bubbles**: user messages right-aligned blue, AI messages left-aligned dark card with Robot avatar
- **Markdown rendering**: uses `react-markdown` for AI responses
- **Auto-scroll**: scrolls to bottom on new messages
- **Loading indicator**: "Thinking..." with CircularProgress shown while waiting for AI response
- **Input field**: multiline TextField with Enter-to-send, send button
- **Props**: `messages`, `onSend`, `loading`, `disabled`, `placeholder`, `error`
- **Empty state**: "No messages yet. Start a conversation!" centered message
- **Error display**: error text centered below messages

### AdminChat (`views/admin/Chat/AdminChat.jsx`)
- **3-panel layout**: left chatbot list (260px), center ChatWindow (flex 1), right settings panel (380px, collapsible via gear icon)
- **Left panel**: chatbot list from `chatbotSlice`, active selection with blue border indicator
- **Center panel**: session dropdown + New/Delete buttons + ChatWindow; auto-creates session on chatbot select
- **Right settings panel**: toggle with gear icon. Shows all config cards:
  1. Basic Info (name, description)
  2. Knowledge Base (select from kbList)
  3. LLM Configuration (provider + dynamic schema fields)
  4. Chain & Memory
  5. Instructions / Prompt Template
  - "Update Settings" button at top and bottom saves via `updateChatbot` thunk
- **Sessions**: auto-created on chatbot select; dropdown for switching; delete with ConfirmDialog
- **Messages**: optimistically added; loaded on session switch

### UserChat (`views/user/UserChat.jsx`)
- **2-panel layout**: left chatbot list, center ChatWindow + session controls
- **Fetches assigned chatbots** from `GET /user/chatbots`
- **Auto-creates session** on chatbot selection if none exists
- **429 rate limit handling**: warning Alert banner when `err.response?.status === 429`
- **Input disabled** when rate limited
- **Empty state**: "No chatbots assigned yet" with icon when user has no access
- **Session management**: dropdown, new, delete with ConfirmDialog

### ChatbotSettingsDialog (modified for M5)
- **Reverted** to simple create/edit dialog (no live chat preview)
- **Added `castValue` function**: converts string input values to proper types (float, integer) based on component schema `type` field — fixes the `temperature` pipeline error where `"0.5"` string was sent instead of `0.5` number
- **`NUMERIC_TYPES` constant**: `['float', 'integer', 'number']` for input field type mapping

## Problems & solutions

### 1. `temperature` pipeline error — type mismatch
**Problem**: `POST /admin/chatbots/{chatbot_id}/sessions/{session_id}/chat` returned "Chat pipeline error: 'temperature'". The cause was that LLM config fields were sent as strings (from TextField) but the backend LangChain component expects numbers.
**Solution**: Added `castValue(value, type)` helper that converts values based on the component schema's `type` field. When type is `"float"`, uses `parseFloat()`. When `"integer"`, uses `parseInt()`. Applied in both `ChatbotSettingsDialog.jsx` and `AdminChat.jsx` settings panel.

### 2. Backend has trailing space in ChatOllama input name
**Problem**: `InputParam(name="temperature " , ...)` in `backend/app/components/Chatmodels/ChatOllama/ChatOllama.py` has a trailing space. The schema sends `name: "temperature "` but the `build()` method looks up `config["temperature"]` (without space). KeyError occurs.
**Note**: This is a backend bug. Cannot fix from frontend. Documented in `tasks.md` under "Backend Bug Found (M5)".

### 3. Live chat preview moved from dialog to sidebar panel
**Problem**: Original M5 spec put live chat preview inside ChatbotSettingsDialog. User requested removing it from there and instead adding a full settings panel to the AdminChat page where the admin can tune settings while chatting live.
**Solution**: 
- Removed live chat preview from `ChatbotSettingsDialog.jsx`
- Removed "Edit Instructions" button from AdminChat top bar
- Added collapsible right settings panel to `AdminChat.jsx` with all chatbot config (name, description, KB, LLM, chain, memory, prompt template) + "Update Settings" save button
- The settings panel is toggled via a gear icon button in the top bar

### 4. Session auto-creation on chatbot select
**Problem**: When selecting a chatbot, if no sessions exist, the message "Select a chatbot" was shown but user couldn't start chatting immediately.
**Solution**: Both AdminChat and UserChat auto-create a session when the selected chatbot has none.

## What NOT to touch

- **`castValue()` in both files** — This handles the numeric type conversion for LLM config fields. If new component types are added (e.g., `"boolean"`), extend this function.
- **`NUMERIC_TYPES` constant** — Used in both files for `type` attribute on TextField and for cast logic. Keep in sync.
- **`ChatWindow.jsx`** — Keep it as a pure presentational component. It should only handle display and input, never API calls.
- **Settings panel collapse state** — Uses `showSettings` useState. Resets to false when selecting a different chatbot.
- **`llm_config.build_config` shape** — Must be `{ name: "ChatOllama", build_config: { base_url, model, temperature } }`. Values in `build_config` must be typed correctly (numbers for temperature, strings for URLs).
- **`Object.entries()` conversion for component schemas** — Same as M3/M4. `listComponents` returns an object, not an array.
