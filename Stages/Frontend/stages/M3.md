## Problems & solutions

### 1. `listComponents(category)` returns an object, not array
**Problem**: The API endpoint `/admin/components?category=X` returns `{ "PyPDFLoader": {...}, "TextLoader": {...} }`. Calling `.map()` on it throws `map is not a function`.
**Solution**: Convert with `Object.entries(data || {}).map(([name, inputs]) => ({ name, inputs }))` **everywhere** the response is consumed. Used in `UpsertionConfigDialog.jsx:52`, `IngestStatusDialog.jsx:43,49`.

### 2. Backend category names don't match what you'd expect
**Problem**: Backend uses `embedder`, `vector_store`, `record_manager` but the `registry.list_all_categories()` returns different casing/format for KB config categories.
**Solution**: Hardcode the 3 config section keys: `embedder`, `vector_store`, `record_manager`. Never assume the category name from a dropdown value.

### 3. MUI `<Grid>` does not render 3 items per row reliably in this context
**Problem**: MUI Grid component was not producing a 3-column layout for cards. Items stretched inconsistently.
**Solution**: Use raw CSS grid: `display: 'grid', gridTemplateColumns: 'repeat(3, 1fr)', gap: 3` on a `<Box>`. Applied in both `DocumentStoreList.jsx:172` and `DocumentStoreDetail.jsx:179`.

### 4. Card aspect ratio needed iterative tuning
**Problem**: Cards started as perfect squares (`1/1`) which looked blocky. Content was cramped.
**Solution**: Iterated through `1/1` → `2/1` → `3/1` → `5/2`. At each step scaled font sizes, icon sizes, and chip text proportionally. Final: `aspectRatio: '5 / 2'`, name `1.3rem` (KB list) / `1rem` (doc cards), stats `0.9rem`, icons 20–24, action buttons 32×32 with 18px icons.

### 5. `POST /admin/knowledge_bases/{id}/upsert` returns 422 "Input should be a valid string"
**CRITICAL BUG — wasted the most time.**
**Root cause**: Backend uses `doc_id: str = Body(...)` without `embed=True`. When `Body()` is used with a single scalar parameter and `embed=False` (default), FastAPI/Pydantic expects the **entire request body to be a JSON string literal** — not `{"doc_id": "value"}` but `"value"` directly.
- Error from FastAPI: `"loc":["body"]` (not `"loc":["body","doc_id"]`), `"msg":"Input should be a valid string"`, `"input":{"doc_id":"..."}` — confirms it tried to parse the whole body as a string and got an object.

**Frontend fix** (since backend cannot be modified): Change the body from `{ doc_id: docId }` (JSON object) to `JSON.stringify(docId)` (JSON-encoded string literal). Axios skips its `transformRequest` when data is already a string, sending the raw JSON string. FastAPI then correctly parses it as the `doc_id` parameter.
- Before: `api.post(url, { doc_id: docId })` → body: `{"doc_id":"uuid"}`
- After: `api.post(url, JSON.stringify(docId))` → body: `"uuid"`
- Change made in `knowledgeBaseApi.js:57`

**Important**: This same issue applies to **any** backend endpoint using `Body()` without `embed=True` with a single scalar parameter. If a future endpoint also returns 422 on valid data, check whether the backend uses raw `Body()` vs a Pydantic model.

### 6. FastAPI 422 error `detail` is an array, not a string
**Problem**: `err.response?.data?.detail` from a 422 validation error is a JSON array of error objects. Passing it to `enqueueSnackbar()` renders a blank gray popup.
**Solution**: In error handling, stringify the error properly:
```javascript
const msg = typeof err === 'string' ? err : JSON.stringify(err?.response?.data || err);
enqueueSnackbar(msg, { variant: 'error' });
```
Applied in `DocumentStoreDetail.jsx:101`.

### 7. Backend `list_uploaded_documents` doesn't include `chunks_count` per document
**Problem**: Frontend needs per-document chunk count. Backend `UploadedDocument` model has no `chunks_count` column.
**Solution**: Backend was modified (outside frontend scope) to pass `extras=loader_counts(d.id, db)` in the `to_dict()` call at `admin.py:449`. Frontend reads `doc.chunks_count ?? 0` directly. **Any agent modifying the frontend must document this dependency** — without the backend change, `chunks_count` will be `undefined` and show `0`.

### 8. `Body(examples=...)` keyword may cause issues in FastAPI/Pydantic v1
**Problem**: The backend uses `doc_id: str = Body(..., examples=["doc_id_..."])`. The `examples` parameter (with 's') was added in FastAPI 0.103.0. With `fastapi==0.104.1` and `pydantic==2.7.4` it works fine. But if the backend were downgraded or if Pydantic v1 were used, this could cause a `TypeError` during route registration.
**Note**: Not an issue for this project's dependency versions, but worth knowing if upgrading/downgrading FastAPI.

### 9. IngestStatusDialog caught in object→array bug (same as #1)
**Problem**: Ingest dialog also calls `listComponents('loader')` / `listComponents('chunker')` which return objects.
**Solution**: Same `Object.entries()` conversion. Applied in `IngestStatusDialog.jsx:43,49`.

### 10. Upsert progress indicator had no visible feedback
**Problem**: The upsert button showed no meaningful progress when clicked. The initial pulse CSS animation was too subtle. Success snackbar popup was unwanted.
**Solution**: Replaced pulse animation with a 3-state icon:
- **Idle**: `IconCloudUpload` in primary blue
- **Loading**: `IconCloudUpload` + spinning `CircularProgress` ring (32px, thickness 2.5) layered with `position: absolute` overlay
- **Success (2s)**: Green `IconCircleCheckFilled` with `setTimeout(() => setRecentUpsert(null), 2000)`
- No success snackbar; error snackbar still shown on failure
- Button color changes: primary blue (idle) → green (success)
- Implemented in `DocumentStoreDetail.jsx:233-243`

### 11. `recentUpsert` state needs per-document tracking
**Problem**: A single boolean `recentUpsert` doesn't work because each doc card has its own upsert button. Multiple docs could be upserted at different times.
**Solution**: Store the **document ID** in `recentUpsert` state, compare with `doc.id` per card: `recentUpsert === doc.id`.

### 12. Naming inconsistencies between frontend and user expectations
**Problem**: Various labels didn't match user expectations:
- "Upsertion Config" → too verbose
- "Load & Chunk Document" → redundant title in dialog
- "View Chunks" → too generic, sounds read-only
- "Welcome to RAGFlow" → unnecessary prefix
**Solution**: Honed to simple labels: "Upsert Config", "Load", "View & Edit Chunks", "RAGFlow".

## What NOT to touch

- **`knowledgeBaseApi.js:57` — `triggerUpsert` sends `JSON.stringify(docId)`** — This is specifically adapted to the backend's `Body()` without `embed=True`. Do NOT wrap it back to `{ doc_id: docId }` unless the backend adds `embed=True`.
- **`kbSlice.js:262-270` — `triggerUpsert` pending/fulfilled/rejected handlers** — The `upsertLoading` state drives the spinner ring on every document card. Do NOT change to per-document loading unless you also rewrite the component to track per-doc loading.
- **Upsert button removed from `ChunksViewDialog.jsx`** — The upsert action lives on each document card in `DocumentStoreDetail.jsx`. Do NOT add it back to ChunksViewDialog without user approval.
- **`StatusChip.jsx` — the status color map** — Every status variant (lowercase AND title-case) is mapped. Adding new statuses without updating this map will show them in neutral gray. Always add both cases.
- **CSS grid (`repeat(3, 1fr)`)** — Both KB list and doc detail views use this. Do NOT revert to MUI `<Grid>`. If responsive behavior is needed, adjust the `gridTemplateColumns` value with breakpoints.
- **`aspectRatio: '5 / 2'`** — Tuned iteratively. Changing it will require rescaling all font sizes, icon sizes, and chip text inside cards.
- **Form field convention in config dialogs** — `UpsertionConfigDialog` fields use `placeholder={String(field.default)}` with **no** `helperText` or `required` prop. This is intentional to match the backend schema behavior. Do not add helper text or required indicators.
- **Backend endpoints that use `Body()` without a Pydantic model** — These expect raw JSON values, not JSON objects. Check `"loc"` in 422 errors: if `"loc":["body"]` (no field name), the body format is wrong. Always look at the error `input` to see what FastAPI actually received vs. what it expected.

## Dependency on backend (frontend cannot fix)

- **`chunks_count` per document** — Backend `admin.py` line 449 adds `extras=loader_counts(d.id, db)`. If the backend doesn't do this, `doc.chunks_count` will be `undefined` (shows `0` via `?? 0`).
- **`POST /upsert` body format** — Backend uses `doc_id: str = Body(...)` without `embed=True`. If backend adds `embed=True`, the frontend can switch back to `{ doc_id: docId }`.
- **Category names** — Backend `registry.list_all_categories()` determines what categories exist. Frontend hardcodes `['embedder', 'vector_store', 'record_manager', 'loader', 'chunker']`. If backend renames a category, update both `UpsertionConfigDialog.jsx:24-27` and `IngestStatusDialog.jsx`.
